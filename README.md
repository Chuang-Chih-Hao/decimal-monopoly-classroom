# 🎲 小數富翁探險島（Decimal Monopoly Classroom）

> **目前版本：v1.7.3** ｜ 國小六年級小數應用 ｜ 繁體中文 ｜ 最多 **6 人連線（房主 1 人＋玩家 5 人）**  
> GitHub 專案：[Chuang-Chih-Hao/decimal-monopoly-classroom](https://github.com/Chuang-Chih-Hao/decimal-monopoly-classroom)

以大富翁為基礎的數學課堂遊戲。學生透過小數運算、折扣、比價、購地、收租、機會與命運卡、Boss 挑戰以及雙人互動小遊戲，在約 30 分鐘內練習數學與資金規劃。房主可建立房間、調整設定、主持遊戲，並在結算後查看學生自填的學習回饋。

> **版本紀錄閱讀方式**：本文記錄從初版到 v1.7.3 的功能演進。**「曾在某版加入」不一定代表現在仍保留該外觀**，例如 v1.2 的車道和 v1.6 的立體旗子均已被後續版本取代。這些版本章節是開發紀錄，不代表 GitHub 已建立同名的 Release 或 Tag。

## 開房與課堂操作

### 教師（房主）

1. 打開部署後的遊戲網址，填寫暱稱、選擇動物，點選「建立房間」。
2. 分享畫面上的房間代碼或邀請連結給學生。房主也是其中一位玩家。
3. 在等待室調整下列四項設定；所有已加入的學生會看見同步設定摘要。
4. 等至少 2 位玩家到齊後開始遊戲。全員可在自己的裝置上擲骰、答題或參加對戰。
5. 遊戲結算時查看排名、全班題型統計與各玩家填寫的文字回饋。

| 房主設定 | 可選值 | 預設 |
|---|---|---|
| 遊戲輪數 | ♾️ 無限輪、2、3、4、5、6、8、10、12 輪 | **無限輪** |
| 每人起始金額 | $600、$900、$1,200 | **$900** |
| 每題作答時間 | 90、120、150、180 秒 | **120 秒** |
| 課堂遊玩時間 | 20、30、40 分鐘 | **30 分鐘** |

**新的課堂互動（v1.7.0）**：當回合玩家解題時，其他人可在自己的裝置上選一個答案參加「觀戰猜題」，不用等到自己回合才有事做；觀戰不加減金錢，也不算進正式答題的學習診斷。命運／機會事件會先有約 25 秒的選擇時間；若逾時未選會自動採用較保守的分支。

**無限輪不是無限時間**：即使設為無限輪，時間到仍會結算；正在進行的題目、購地或雙人對戰，會在該流程處理完後再結算。房主也可以提早手動結束。計時是「最多可用時間」，學生算完就可以立即作答，**不需要等倒數結束**。

### 學生（一般玩家）

1. 輸入暱稱與房間代碼，選擇尚未被別人使用的動物。
2. 在等待室確認四項遊戲設定；一般玩家只能查看，不能更改。
3. 輪到自己時擲骰，看動物跳到目的格，依畫面提示答題、購地或參加互動。
4. 可點「我的資產」查看現金、房產價值及房產位置，也可自行調整棋盤視野。
5. 結束時查看個人錯題與學習建議，並填寫「數學冒險家回饋」。

## 遊戲規則

### 棋盤、房產與資產

- 全圖 30 格，其中 **13 格可購買房產**；其餘包含折扣、比價、小數計算、黑心商人、機會、命運、寶箱、Boss、稅務、休息補給與起點。
- 無主房產：需先**答對購地題**，才可決定是否花費遊戲幣購買。答錯無法取得該地。
- 已有屋主的房產：租客先繳地圖標示的**過路費**，再依狀態觸發屋主與租客的雙人互動。
- 租金不足：先進入數學救援題；答對時可獲得補助以處理租金，答錯則依救援規則處理現有現金與暫停回合。
- 經過或到達起點可領取 $200；補給休息站提供 $30。稅務局收取 $60。
- **結算總資產 = 手上現金＋所擁有房產的購入價格總和**；總資產相同時，依答對題數判定順序。

所有金額都是**遊戲內虛擬幣**，不牽涉真實金錢或真實賭博。

### 題目與特殊格

- 小數計算：小數加減乘除及情境應用。
- 折扣題：明確說明折數與折後價格，例如「原價 $80，打 7.5 折」代表付原價的 75%，**折後售價 $60、節省 $20**。
- 比價題：比較不同包裝、重量或數量的單位價格。
- 黑心商人：辨認不合理計價、換算與折扣陷阱。
- 寶箱、機會、命運：配合情境答題，依結果給予獎金、扣款或其他事件。
- Boss：連續挑戰兩道題目，依答對題數獲得不同獎勵。
- 題庫附有解題說明；未作答前，正確答案由伺服器保管，不會直接送到前端。

### 屋主與租客的雙人小遊戲

- **先付租金，再玩小遊戲**；小遊戲輸贏不會取消原本的過路費。
- **猜拳**：石頭、布、剪刀。兩人各自在自己的裝置上出招；平手可再玩，最多 3 回合。
- **烏龜烏龜翹（專案自訂簡化版）**：雙方各選 1～5 根手指；同數量時由本回合指定的攻擊方獲勝，不同則交換攻守，最多 4 回合。
- 出招最多等待 25 秒；未揭曉前對方無法偷看手勢。逾時、平手或離線皆有收尾規則，避免拖住全班。
- 勝負成立時，輸家額外付給贏家最多 $40；**後段衝刺最多 $60**，且最多只支付手上還有的現金。
- 房主可在必要時跳過對戰；跳過不額外轉帳。

## 學習回饋與資料說明

**個人回饋**：結算後，每位學生能看到本局答題數、答對數、正確率、逾時題數、需要複習的題型與最多 6 題錯題解析。能力分類是：**小數加減、小數乘法、小數除法、折扣與折數、單價比價、多步驟應用**。

**全班統整**：所有玩家可看到不具名的題型錯誤統計，方便老師安排下次複習；不會公開他人的個人錯題內容。房主跳過的題目不計入學生錯題。若某題型抽樣很少，報告只是複習線索，不代表正式能力測驗。

**文字回饋**：在「數學冒險家回饋」文字框輸入最多 600 字，送出後可再次修改。只有**本人與房主**能查看該玩家的文字內容，房主可檢視回收狀態。

> ⚠️ **資料保存限制**：目前房間、資產、作答歷史及文字回饋僅保留於伺服器記憶體。Render 重啟、重新部署、休眠導致服務重啟或重新開局，都可能使資料消失。這個版本沒有提供長期資料庫、匯出報表或跨場次的學習歷程保存功能。

### v1.7.3｜購地動畫只顯示房子，修復全圖大色塊與縮放異常（2026-11-04）

**問題原因**：先前建造動畫使用 `tile-effect-build` 同時作為整個棋盤格的狀態類別及動畫內層容器的類別。CSS 選擇器 `.board .tile-effect-build` 設定 `width:100%`、`height:100%`、`display:flex`，誤套到實際地圖格，讓格子被撐大並覆蓋附近區域；購地動畫另帶有漸層背景、彩色框及多個圖示，在全景與縮放時尤為明顯。

**本次修改摘要**：
- **狀態類別去衝突**：購地時棋盤格只加入 `tile-effect-building` 狀態；與真正的動畫子元素命名分離，避免對地圖格套用額外的 100% 寬高或 flex 排版。
- **只播放一棟房子的動畫**：購地成功的那一格僅顯示一個「🏠」由下升起、縮放定格的動畫；移除額外的店面符號、槌子、閃光、浮動標籤與彩色框。
- **移除彩色遮罩**：建造動畫圖層採完全透明背景、無漸層、無邊框與陰影色塊，並以 `inset:0`、`width:100%`、`height:100%` 限制於**單一被購買的小格內部**；動畫會裁切在格子內，避免全景縮放時覆蓋其他格。
- **保留原圖切換邏輯**：播放時暫時隱藏該格原本的主圖示與常駐背景裝飾；動畫結束或被中斷時清除狀態並自動恢復。格子名稱、價格、屋主與其他角色不受影響。
- **維持無障礙設定**：在減少動態效果模式下不播放房子彈跳動畫，但仍顯示房子圖示。
- 套件版本與 HTML 前端快取參數更新至 `1.7.3`，擴充動畫尺寸隔離與無背景色塊的回歸測試。

**保留功能**：原有 30 格棋盤、動物跳躍、其他類型落點動畫、購地判定與收租、多人觀戰猜題、劇情機會／命運、成就稱號、動態調整的答題面板及學習回饋都不更動。

**修改檔案**：`public/app.js`、`public/style.css`、`public/index.html`、`package.json`、`test/ui-layout.test.js`、`README.md`。

### v1.7.2｜數學題出現時置頂，作答完成後恢復回合操作區（2026-11-04）

**需求與原因**：遊戲進行時需要優先看到數學題，而不是先看到「NOW PLAYING」提示；當題目回答完畢，又應立刻回到擲骰／結束回合的操作位置。解題解析始終顯示在操作區下方，讓答題與操作的視覺重心隨遊戲階段切換。

**本次修改摘要**：
- **答題／劇情進行中**：右側順序變成「我的資產 → 數學題目或劇情選擇 → NOW PLAYING 回合操作 → 解題解析 → 財富排行榜 → 預設收合的成就 → 房主控制台」。
- **題目作答完成後**：題目自動回到原本的位置；**NOW PLAYING** 重新排到資產下方，答題解析則維持在操作區下方。購地題答對後若需要選擇是否購買，購地確認區也維持在操作區之後，不會再次把操作區推下去。
- **不重建整個側邊欄**：只利用 `insertBefore` 移動既有的題目 DOM 節點；不會因此刪除按鈕事件或重新建立成就面板，也不會干擾已展開的成就。
- **平板優化**：在 641～960px 的雙欄斷點中，將資產、題目、操作、雙人對戰與解析區設為單列跨欄顯示，避免題目與資產同排，確保題目真的位於資產下面。
- 更新前端資源快取與套件版本至 `1.7.2`，加入題目優先／完成後復原的介面回歸測試。

**不變功能**：維持原本 30 格地圖、角色跳格與事件動畫、多人即時觀戰猜題、命運／機會分支、8 種成就及摺疊、題庫、購地／租金、結算回饋。無需更動伺服器計算與資料格式。

**修改檔案**：`public/app.js`、`public/style.css`、`public/index.html`、`package.json`、`test/ui-layout.test.js`、`README.md`。

### v1.7.1｜恢復回合／答題面板優先順序，成就改為預設收合（2026-11-04）

**問題原因**：v1.7.0 將 8 格大型成就面板插入「我的資產」與「NOW PLAYING」之間，讓擲骰、回合按鈕與答題面板被推到右欄下方，尤其在電腦畫面不方便操作。

**本次修改摘要**：
- **右側面板恢復優先順序**：我的資產 → NOW PLAYING（擲骰與回合按鈕）→ 雙人對戰／數學題目／答題解析 → 財富排行榜 → **我的冒險成就** → 房主控制台（僅房主可見）。
- **成就面板移到排行榜之後**，改用原生 HTML `<details>` 和 `<summary>`，進入遊戲預設收合，避免 8 張成就卡佔用首屏空間。
- **收合時保留重要摘要**：顯示「🏅 我的冒險成就」、已解鎖數量（例如 3 / 8）及目前裝備的稱號。點擊可展開／收合，展開後仍可查看完整成就條件、觀戰猜題紀錄和「設為稱號」按鈕。
- **Socket.IO 狀態刷新不強制收合**：前端只更新標題中的數量與稱號、以及成就內容容器，不重新建立 `<details>`，避免遊戲狀態更新時把使用者主動展開的面板關閉。
- **手機與鍵盤可操作**：依瀏覽器原生 `<details>` 互動提供鍵盤支援、展開狀態以及聚焦樣式；手機版收合標頭縮小內距。
- 版本號、HTML 資源快取參數及相關介面回歸測試更新到 **v1.7.1**。

**保留功能**：不更動伺服器、題庫、遊戲金錢平衡、觀戰猜題、劇情式機會與命運、8 種成就解鎖規則、成就稱號、動物與地圖動畫、學習回饋及連線流程。

**修改檔案**：`public/index.html`、`public/app.js`、`public/style.css`、`test/ui-layout.test.js`、`package.json`、`README.md`。

### v1.7.0｜全員觀戰猜題＋劇情式命運與機會＋冒險家成就稱號（2026-11-04）

**版本目標**：解決非當回合玩家容易等待無聊的問題，將命運／機會從單純抽卡改成有風險選擇的故事，並讓排名落後的學生也能靠學習表現取得成就感。本版保留六人連線、30 格棋盤與現有小數題庫。

**一、全員觀戰猜題（即時多人參與）**
- 除當回合正式答題者外，房內其他玩家均能用自己的裝置選 A／B／C／D 觀戰猜題，每題最多猜一次，不可修改。
- 觀戰猜題送到伺服器保管；正式玩家與其他觀眾在題目揭曉前**不能看到其他人的選項**，只有本人看得到「我已選擇」的狀態。
- 觀戰者和正式玩家共用題目及截止時間，逾時後停止接受猜題。
- 正式玩家回答或逾時後，公布「觀戰共 N 人參加，M 人猜對」及本人是否猜對；不公開其他學生的個別錯誤答案。
- **觀戰不影響經濟與學習統計**：不增加或扣除現金，不影響正式答題次數、正確率、學習弱項或金錢排行。房主略過題目時，不計算該題觀戰成績。
- 觀戰猜對累積 3 題可取得「觀戰智多星」成就。

**二、劇情式命運／機會事件**
- 走到機會或命運格時，先顯示與該張卡對應的生活場景故事，玩家選擇「🛡️ 穩健處理」或「🎲 冒險挑戰」。
- 兩條分支會**先公開答對獎勵與答錯損失**，學生可練習比較風險與報酬；選完才出現原本機會／命運的數學題。
- 穩健分支的失敗損失最多 $20，通常獎勵較少；冒險分支答對獎金較高，但仍承擔卡片原本可能的損失。所有金額均是遊戲虛擬幣，付款不會超出現金餘額。
- 選擇階段預設 25 秒；逾時自動選穩健分支，再開始正常的 90／120／150／180 秒數學題倒數。房主可跳過劇情事件，防止課堂卡住。
- 選過冒險分支可取得「命運冒險家」稱號。劇情事件使用既有機會／命運數學題庫，不新增超出六年級能力範圍的新題型。

**三、成就系統與冒險家稱號**
- 共 8 個可解鎖成就：🌟 小數新星、🧮 計算達人、🏷️ 折扣高手、🔎 比價偵探、🏠 店面新星、🏘️ 島嶼經營家、👀 觀戰智多星、🔮 命運冒險家。
- 正式答題、對應數學能力、購地、觀戰猜對及劇情選擇會由伺服器檢查成就條件，不接受客戶端任意宣告解鎖。
- 在「我的冒險成就」面板查看解鎖狀況、解鎖條件與個人觀戰猜對數；可將已獲得的成就設定為目前稱號，顯示在排行榜與結算畫面。
- 成就沒有現金加成，也不改變房產價值或排名；每局結束保留本局成果，房主重新開局後重設成就與觀戰成績。

**安全與相容性**：觀戰選項與劇情決策在 Socket.IO 伺服器端驗證身分、回合與截止時間；正確答案仍只保留在伺服器端直至題目揭曉。舊版本的動物跳格、專屬格子動畫、購地建築效果、房主操作、個人錯題隱私與多人租後對戰保留不變。

**部署注意**：這次涉及 Socket.IO 新事件與伺服器房間狀態，既有房間資料仍存放在記憶體。Render 新版本部署會重啟服務，因此請避免在課堂正在遊玩時更新。部署後所有裝置應重新載入頁面以獲取 v1.7.0。

**原本問題**：若只用固定輪數，課堂可能在預定 30 分鐘之前就結束；只公布財富排名，老師不容易看出學生常錯的小數題型。

**本版修改**：
- 新增並預設選取 **♾️ 無限輪**；只取消輪數限制，**仍保留 20／30／40 分鐘**的遊玩時間，以及房主手動結束功能。
- 結算時增加每人的題目統計：作答／答對／答錯、正確率、逾時次數及至多 6 題錯題解析。
- 用真正的**數學能力分類**整理常錯題型，而非按「機會格、命運格、寶箱格」混合統計。
- 顯示最多 3 個優先複習的薄弱題型及建議；全班畫面顯示**匿名**共同錯題分布。
- 房主跳過的題目不計入學生答題紀錄；重新開局重置當局學習統計。

**使用者感受到的差異**：一堂約 30 分鐘的課不會因輪數不足提早結束；結束後除了輸贏還可以回顧自己哪一類小數運算需要加強。

**技術更新**：新增 `feedback.js` 處理學習統計，個人錯題資料按玩家身分分別傳送。

### v1.3.0｜經典方格大富翁地圖、全員聚焦與資產配色

**原本問題**：v1.2 的彎曲車道不像傳統大富翁；地圖太大時大家不容易看到目前玩家；房產與玩家身分對照不夠清楚。

**本版修改**：
- 將地圖改為 **30 格的 10 欄 × 7 列方形外圈**，中間顯示標題、骰子與目前玩家資訊，不再畫車道。
- 每次換到下一位玩家，全房間的地圖會自動聚焦到該玩家附近；聚焦完仍可用縮放按鈕、滑鼠拖曳、觸控滑動自由查看。
- 新增 12 隻動物的固定代表色；棋子、房產屋主標示、排行榜及個人資產卡一致套用。
- 新增「我的資產」詳細列表，拆開顯示**現金、房產總值、總資產**，並能點選土地定位。

**使用者感受到的差異**：棋盤更像熟悉的大富翁桌遊，全班能跟著目前玩家看見落點，也更容易分辨哪間店是自己的。

**技術更新**：加入 `public/board-layout.js` 與 `public/player-colors.js`，需和前端一起部署。

### v1.2.0｜擴大至 30 格、延長答題時間、租後雙人互動

**原本問題**：舊地圖格數偏少，題目時間不足六年級學生使用紙筆計算；遊戲到中後期變化不足，踩到別人土地時只扣租金缺少互動。

**本版修改**：
- 棋盤由 **24 格擴充至 30 格**，增加房產與特殊事件；**當時採彎曲車道外觀（已被 v1.3 取代）**。
- 作答預設時間改為 **120 秒**，可延長到 150／180 秒，也可選 90 秒；Boss 題目依題計時。
- 增加以 **30 分鐘**為主的課堂遊玩時間設定，並設計中場與最後衝刺的獎勵變化。
- 踩到其他玩家房產時先收租，再由真實的**屋主與租客**同步進行猜拳或簡化版烏龜烏龜翹，勝負增加虛擬零用錢轉帳。
- 對戰提供倒數、最高回合數與平手處理，避免互動卡住全班。
- 針對 **91 題**補充已知條件、計算目標、單位與解題說明，特別加強折扣與比價題目的文字清晰度。

**使用者感受到的差異**：學生有較充足的時間理解題意、手算與檢查；更多格子與租後對戰讓 30 分鐘遊戲的節奏更有變化。

### v1.1.0｜骰子、逐格移動與事件提示動畫

**原本問題**：擲骰後玩家只看到最終格子，不知道擲出了幾點；事件紀錄藏在角落，不易注意到金額與落點；部分題目解析不夠完整。

**本版修改**：
- 加入醒目的骰子滾動和**點數揭曉**效果，骰子仍由伺服器決定，不是前端自行隨機產生。
- 角色改為依骰子點數**逐格移動**，落點與特殊事件會高亮及彈出提示；最新事件紀錄較易識別。
- 修正「原價 $80、打 7.5 折」的解說：**7.5 折 = 75%**，折後價 `80 × 0.75 = 60`，節省 `80 − 60 = 20`；明確區分「實際售價」和「省下多少」。

**使用者感受到的差異**：每次擲骰、前進與答題成功／失敗都更容易被全班看見，降低學生誤解遊戲進度的機會。

### v1.0.0｜最初可遊玩的多人數學大富翁

**初版內容**：
- 以 Node.js、Express 與 Socket.IO 提供多人房間；房主加最多五位學生可透過房間碼加入。
- 提供動物棋子、擲骰前進、現金與房產、經過起點領錢、繳交過路費，以及機會／命運類特殊格。
- 將購買土地、折扣、比價、黑心商人、寶箱、Boss 和資金不足時的救援，設計成小數應用題。
- 答題與資金、房產所有權由伺服器統一判定，避免不同裝置看到不同結算。
- 初版採 **24 格地圖**，後續經 v1.1、v1.2 與 v1.3 逐步改善可視化、題目敘述及課堂節奏。

## 本機開發與測試

需求：**Node.js 20 以上**。

```bash
npm install
npm start
```

在瀏覽器開啟 `http://localhost:3000`。開發時可用 `npm run dev`；自動測試使用：

```bash
npm test
```

截至 **2026-11-04（v1.6.2）**，本機執行 `npm test` 為 **44 項通過、0 項失敗**。測試主要涵蓋題庫、30 格座標、動物代碼與配色、購地與收租、對戰判定、時間／輪數結算、等待室設定、學習回饋與權限限制。**自動單元測試通過不代表已完成真實 6 人同時在線的正式環境壓力測試**；實際上課前建議至少用兩台裝置試玩。

## GitHub 與 Render 部署

### 已有 GitHub 專案：更新既有檔案

1. 在學生遊戲**結束後**再更新，以免 Render 重啟使目前房間遺失。
2. 確認 GitHub `main` 分支是你目前要使用的版本，先保留備份。
3. 更新程式時，將完整新版專案的檔案**依相同路徑覆蓋**，例如 `public/app.js` 覆蓋 `public/app.js`；不要直接把整個 ZIP 當成一個檔案傳到 GitHub。
4. **如果只更新 README**，僅替換根目錄的 `README.md` 即可，**不需要重新上傳整個程式或更改 `package.json` 版本號**。
5. Commit 到 `main` 後，Render 若啟用自動部署，可能因新 commit 重啟服務。確認服務狀態為 **Live** 後再請學生入場。

### 首次部署：Render Blueprint

在儲存庫根目錄保留 `render.yaml`（與 `package.json` 同層），到 [Render Dashboard](https://dashboard.render.com/) 建立 **New → Blueprint**，選擇該儲存庫及 `main` 分支，Blueprint Path 使用 `render.yaml`。

`render.yaml` 預設內容：Node Web Service、Singapore、Free、`npm install --omit=dev`、`npm start`、健康檢查 `/health`。也可以手動建立 Node Web Service，使用相同的 Build 與 Start 指令。

## 已知限制與排除方式

| 狀況 | 說明／建議 |
|---|---|
| 學生看不到新版等待室設定 | 確認 Render 已部署最新 commit，再讓學生重新整理舊分頁；v1.5.1 後有版本偵測與防快取改進 |
| 動物圖案仍是舊選項 | 確認 GitHub 與部署版本均是 v1.6.2；重新整理瀏覽器，並確認 `board.js`、`public/app.js`、`public/player-colors.js` 使用同一份動物清單 |
| 棋子變回旗子 | 代表誤用了 v1.6 的前端檔案；請改用 **v1.6.1／v1.6.2** 的 `public/app.js` 和 `public/style.css` |
| 無限輪仍然結束 | 無限輪只取消**輪數限制**，仍受設定的 20／30／40 分鐘限制 |
| 學生突然無法繼續先前遊戲 | Render 重新部署、重啟或房間被清除後，記憶體中的進度不會自動恢復 |
| 文字回饋不見 | 目前沒有永久資料庫，結算後建議教師先閱讀、整理，再結束房間或部署 |
| 多人操作時間不同步 | 檢查各裝置網路與 Render 服務狀態；以伺服器的狀態和計時為準 |
