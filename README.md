# 🎲 小數富翁探險島 — v1.2（30 格彎曲賽道、雙人小遊戲）

國小六年級小數應用線上大富翁，**1 位房主＋最多 5 位學生（6 人）**同步遊玩。使用繁體中文，電腦、平板和手機瀏覽器皆可開啟。房主本身是遊戲中的一位玩家，也可控制開局、跳過回合和結算。

## v1.2 這次修改了什麼？

| 項目 | 新版設計 |
|---|---|
| 答題時間 | **120 秒預設**；房主可設定 90／120／150／180 秒。每題獨立計時，Boss 兩題各自計時。 |
| 彎曲地圖 | **30 格彎曲環形車道**，非正方形棋盤；保留擲骰動畫、逐格移動和最新事件彈窗。 |
| 課堂時間 | **30 分鐘預設**，亦可選 20／40 分鐘，搭配最多 12 輪；以「輪數上限或時間上限」先到者為準。正在回答／購地／對戰時不會硬切，完成這個回合再結算，因此可能稍晚結束。 |
| 兩人對戰 | 踩到**其他玩家已買下的房產**時，先繳固定過路費，再由屋主與租客在各自裝置上玩猜拳或烏龜烏龜翹。不是由電腦代出招。 |
| 對戰零用錢 | 勝者收取虛擬幣，輸家再付**最多 $40**；最後三分之一時段最多 $60。輸家最多付出現有現金，不會負債。平手不轉帳。 |
| 避免拖延 | 每回合小遊戲最多 25 秒出招時間；猜拳最多 3 次、烏龜烏龜翹最多 4 次。同時出招才揭露答案；僅一人出招且對方逾時，已出招者勝出；皆未出招則平手。 |
| 後段加碼 | 經過 1/3 時間後，特殊格數學題答對另加 $30；進入最後 1/3 時段加 $60，同時對戰補貼上限提升。 |
| 詳細題目 | **91 題全面重寫情境文字**：加入已知條件、要計算什麼、單位與折數意義，保留原有選擇題答案和作答後解說。 |

> 機會／命運卡、寶箱、黑心商人、Boss、購地與救援題依然以小數應用為核心。所有房產、金額和正確答案由伺服器管理，尚未作答時不會把答案傳給網頁。

## 推薦的 30 分鐘班級玩法

- 房主在教室投影遊戲地圖，預設 **12 輪、$900、120 秒、30 分鐘**。實際上多半會由 30 分鐘倒數決定何時結束，因為一輪是全體玩家各走一次。
- 答題倒數 120 秒是**每題最多可用時間**，不是每題都必須等 2 分鐘。算完即可立刻提交；房主可視班級程度選 150 或 180 秒。
- 20 分鐘左右遊戲會進入最後衝刺階段，金錢獎勵加碼以維持參與度。
- 每次有房產互動時，租客**先付租金**，再和**實際房產擁有人**比手勢；勝負不會抵銷原本應付的過路費。
- 如果租客租金不足，會先進入**數學救援題**；答完後，如果兩人仍在線，就進行對戰。

## 雙人小遊戲的玩法

- **猜拳**：石頭、布、剪刀，兩人都出拳後比較。平手重賽，最多 3 次。勝負以一般猜拳規則判定。
- **烏龜烏龜翹（本遊戲自訂簡化版）**：雙方同時選 1～5 根手指。系統指定一方當攻擊方；兩人選同數量時由攻擊方獲勝，不同則換人攻擊；最多 4 次。這是方便網路同步的簡化玩法，不等同所有實體遊戲版本。
- 對戰雙方需要各自按按鈕；未出拳前不會公開給對方知道。每次出招最多等 25 秒。只有勝負成立時才移轉額外零用錢。
- 若其中一方離線，當次僅收原租金，不強制加賽；房主亦可跳過正在進行的對戰。

## 30 格地圖與經濟系統

- 30 格包含 **13 處可購買房產**，以及機會、命運、折扣、比價、黑心商人、寶箱、Boss、稅務局、補給站、起點等。
- 經過或抵達起點得 $200；補給站得 $30；無主房產必須答對題目才可選擇購買。
- 當玩家停到其他玩家的房產，會支付地圖上顯示的租金；本版增加租後雙人對戰。
- 租金不足時需回答救援題：答對可由學習基金補足差額給屋主；答錯交出現有現金，下一個輪到自己的回合暫停一次擲骰；之後依狀態仍可能進入雙人小遊戲。
- 黑心商人與寶箱會依答題結果給予獎勵／扣款；Boss 有連續兩題挑戰；機會與命運仍會抽事件卡後答題。
- **結算總資產 = 現有遊戲幣＋房產購入價格總和**；同分按答對題數排序。
- 這些「金錢」皆為**遊戲中的虛擬幣**，不涉及真實交易或賭博；不會以現金負債淘汰學生。

## 更新已經部署的 GitHub／Render 專案

1. 先**備份 GitHub 原本檔案**，選擇「v1.2 僅更新檔案 ZIP」並**解壓縮**。
2. 打開 GitHub 原本的 `decimal-monopoly-classroom` 儲存庫，確認目前在 `main` 分支。
3. 把解壓縮後的檔案**按相同路徑替換**：例如 `public/app.js` 要覆蓋 GitHub 內的 `public/app.js`，而不是將 ZIP 直接放入儲存庫。
4. 提交變更（Commit changes）。如果 Render 的 Web Service 開啟 GitHub 自動部署，新的 Commit 會觸發重新部署。也可以到 Render 的服務頁手動選 **Manual Deploy → Deploy latest commit**。
5. 服務變成 **Live** 後，用原本 Render 網址開啟遊戲；建議先用兩個瀏覽器視窗進房，測試擲骰、題目與租後對戰。

> ⚠️ **不要在學生正在玩的房間中重新部署。** 目前房間與資產只保存在伺服器的記憶體中；Render 重新啟動、重新部署或閒置休眠後房間會消失。若需跨堂保留紀錄，需另加資料庫持久化。

## 全新部署到 GitHub 與 Render

**本機執行**：Node.js 20 以上，在專案資料夾執行：

```bash
npm install
npm start
```

在瀏覽器打開 `http://localhost:3000`。遊戲規則自動測試：

```bash
npm test
```

**GitHub**：新建或使用現有的 `decimal-monopoly-classroom` Repository，將**所有檔案（非單一 ZIP）**上傳到儲存庫根目錄，`render.yaml` 要與 `package.json` 在同一層。

**Render**：開啟 https://dashboard.render.com/ ，使用 New → Blueprint，連接 GitHub 儲存庫，分支選 `main`，Blueprint Path 保持 `render.yaml`。專案內 `render.yaml` 已設定：

- Runtime：Node
- Region：Singapore
- Build：`npm install --omit=dev`
- Start：`npm start`
- Health Check：`/health`
- Plan：`free`

不使用 Blueprint 時，也可手動建立 Node Web Service 並填入相同 Build／Start 命令。
