# 🎲 圓形富翁探險島（Circle Monopoly Classroom）

> **目前版本：v2.2.0** ｜ 國小六年級圓周長與圓面積 ｜ 繁體中文 ｜ 最多 **6 位玩家（真人與機器人合計）**  
> GitHub 專案：[Chuang-Chih-Hao/decimal-monopoly-classroom](https://github.com/Chuang-Chih-Hao/decimal-monopoly-classroom)

以大富翁為基礎的數學課堂遊戲。本週課程主題為**圓周長與圓面積**（全題庫圓周率統一採 **3.14**）。學生透過半徑、直徑、圓周長、圓面積、半圓、圓環與生活情境應用，配合購地、收租、機會與命運卡、Boss 挑戰與雙人互動，在約 30 分鐘內練習六年級幾何與資金規劃。房主可建立房間、調整設定、主持遊戲，並在結算後查看學生自填的學習回饋。

> **版本紀錄閱讀方式**：本文記錄從初版到 v2.2.0 的功能演進。**「曾在某版加入」不一定代表現在仍保留該外觀**，例如 v1.2 的車道和 v1.6 的立體旗子均已被後續版本取代。這些版本章節是開發紀錄，不代表 GitHub 已建立同名的 Release 或 Tag。

## 開房與課堂操作

### 教師（房主）

1. 打開部署後的遊戲網址，填寫暱稱、選擇動物，點選「建立房間」。
2. 分享畫面上的房間代碼或邀請連結給學生；也可以在等待室使用「＋ 新增機器人」填入空位。房主本身也是一位玩家。
3. 在等待室調整下列四項設定；所有已加入的學生會看見同步設定摘要。
4. 等至少 2 位玩家（含機器人）就位後開始遊戲。真人在自己的裝置上擲骰、答題或參加對戰；機器人由伺服器自動操作。
5. 遊戲結算時查看排名、全班題型統計與各玩家填寫的文字回饋。

| 房主設定 | 可選值 | 預設 |
|---|---|---|
| 遊戲輪數 | ♾️ 無限輪、2、3、4、5、6、8、10、12 輪 | **無限輪** |
| 每人起始金額 | $600、$900、$1,200 | **$900** |
| 每題作答時間 | 90、120、150、180 秒 | **120 秒** |
| 課堂遊玩時間 | 20、30、40 分鐘 | **30 分鐘** |

**音效操作（v1.8.1）**：所有頁面頂部都有「🔉 音效開啟／🔇 已靜音」按鈕、音量滑桿與 ♫ 試聽鍵。預設音效開啟、音量 **18%**，適合多人課堂環境；可自行降低音量或直接靜音，偏好儲存在這台裝置的瀏覽器，不會影響其他學生。瀏覽器有自動播放限制，因此第一次需要先點擊網頁、擲骰或按試聽鍵才會開啟聲音；不是由伺服器強制播放。音效使用內建 Web Audio 合成，不依賴外部音檔或音樂授權，沒有網路額外下載。若裝置不支援 Web Audio，遊戲仍可正常進行，只是沒有聲音。

**機器人操作（v1.8.0）**：房主在等待室可點「＋ 新增機器人」逐一填滿空席，每台自動選擇尚未使用的動物，房主可按該席位上的「移除」。總數仍限 6 位，開始遊戲後不可再增減。機器人會自動擲骰、解題（平均設定約 65% 正確率，不會每題都答對）、抽機會／命運牌、決定是否買房、完成雙人對戰以及觀戰猜題。所有行動由伺服器定時處理，等待格子演出有數秒節奏；無須建立其他分頁或帳號。機器人會照常持有房產、付款收租並加入財富排行榜，但其數學作答不會計入老師的全班學習統計，機器人也不會出現在學生文字回饋名單。機器人在結算後保留席位，房主重開局時仍可移除。

**課堂互動**：當回合玩家答題時，其他人可在自己裝置上觀戰猜題，不加減遊戲幣，也不算正式學習統計；本版觀戰者同樣可使用私人計算紙。機會／命運已由舊的劇情分支改為抽牌，45 秒未抽則自動翻牌。

**無限輪不是無限時間**：即使設為無限輪，時間到仍會結算；正在進行的題目、購地或雙人對戰，會在該流程處理完後再結算。房主也可以提早手動結束。計時是「最多可用時間」，學生算完就可以立即作答，**不需要等倒數結束**。

### 學生（一般玩家）

1. 輸入暱稱與房間代碼，選擇尚未被別人使用的動物。
2. 在等待室確認四項遊戲設定；一般玩家只能查看，不能更改。
3. 輪到自己時擲骰，看動物跳到目的格，依畫面提示答題、抽牌、購地或參加互動。答題時可按「✏️ 打開計算紙與計算機」，在草稿紙上書寫、擦拭與計算，再選擇答案。
4. 可點「我的資產」查看現金、房產價值及房產位置，也可自行調整棋盤視野。
5. 結束時查看個人錯題與學習建議，並填寫「數學冒險家回饋」。

## 遊戲規則

### 棋盤、房產與資產

- 全圖 **32 格（11×7 長方形外圈）**，其中 **13 格可購買房產**；其餘包含圓周長、圓面積、兩圓比較、公式陷阱、機會、命運、圓形寶箱、Boss、監獄、均付、稅務、休息補給與起點。
- 無主房產：需先**答對購地題**，才可決定是否花費遊戲幣購買。答錯無法取得該地。
- 已有屋主的房產：租客通常先繳**過路費**再進行雙人小遊戲；若身上有「租金保護券」，則消耗一次保護券免付過路費、也不進行加賽。
- 租金不足：先進入數學救援題；答對時可獲得補助以處理租金，答錯則依救援規則處理現有現金與暫停回合。
- 經過或到達起點可領取 $200；補給休息站提供 $30。稅務局收取 $60。
- **結算總資產 = 手上現金＋所擁有房產的購入價格總和**；總資產相同時，依答對題數判定順序。

所有金額都是**遊戲內虛擬幣**，不牽涉真實金錢或真實賭博。

### 題目與特殊格

- **圓周率統一取 3.14**，所有題目的題幹都明示近似值；回答以題目要求的公分、公尺、平方公分或平方公尺為準，不混用周長與面積單位。
- **圓周長**：已知半徑或直徑算圓周長，圓周長＝直徑 × 3.14＝半徑 × 2 × 3.14。統一使用「圓周長」，不再稱「圓周界」。
- **圓面積**：已知半徑或直徑計算整圓面積，面積＝半徑 × 半徑 × 3.14，單位需有「平方」。
- **逆推與比較**：知道周長求直徑或半徑；比較兩圓的周長或面積，辨認半徑加倍時周長與面積變化。
- **半圓與複合圖形**：半圓面積、含直徑的**半圓周長**、圓環面積與正方形內切圓剩餘面積，均有逐步解析。
- **對應圖案**：題目與解題解析同步呈現 SVG 圓形示意圖，按題目已知數值畫半徑、直徑、雙圓、半圓、圓環或內切圓。已知周長要反推半徑時，圖上不會先寫出答案。
- **地圖格**：原本的「折扣百貨、比價擂台、黑心商人、小數神算、精打細算站」改為圓面積研究所、雙圓比較站、公式陷阱站、圓周長挑戰、半徑觀察站；保留原商店動畫與價格。
- **寶箱、機會與命運**：寶箱可能抽出圓形數學題；機會與命運各有 12 張隨機牌，不一定需要答題，可能獲得寶物、與玩家互相贈送／收取金錢、取得租金保護券或下回合暫停；Boss 仍連續挑戰兩題。
- **觀念題與是非題**：依格子功能抽不同學習範圍，公式陷阱含是非判斷，面積格主要練面積、周長格主要練周長、Boss 以複合題為主。是非題提供「正確／錯誤」兩個選項。
- **計算難度**：π 固定 3.14，其他小數答案通常四捨五入至第一位；解題解析將四捨五入結果使用「約等於」表示。題庫附完整公式與解題提醒；未答題前不傳送正確答案。
- **題目出現時機**：動物完成逐格跳躍、抵達目標格後才顯示題目或抽牌介面；動畫中無法提前看到題目。

### 屋主與租客的雙人小遊戲

- **先付租金，再玩小遊戲**；小遊戲輸贏不會取消原本的過路費。
- **猜拳**：石頭、布、剪刀。兩人各自在自己的裝置上出招；平手可再玩，最多 3 回合。
- 出招最多等待 25 秒；未揭曉前對方無法偷看手勢。逾時、平手或離線皆有收尾規則，避免拖住全班。
- 勝負成立時，輸家額外付給贏家最多 $40；**後段衝刺最多 $60**，且最多只支付手上還有的現金。
- 房主可在必要時跳過對戰；跳過不額外轉帳。

## 學習回饋與資料說明

**個人回饋**：結算後，每位學生能看到本局答題數、答對數、正確率、逾時題數、需要複習的題型與最多 6 題錯題解析。能力分類已改為：**半徑與直徑、圓周長計算、圓面積計算、由周長反求半徑、兩圓周長與面積比較、半圓與複合圖形**。

**全班統整**：所有玩家可看到不具名的題型錯誤統計，方便老師安排下次複習；不會公開他人的個人錯題內容。房主跳過的題目不計入學生錯題。若某題型抽樣很少，報告只是複習線索，不代表正式能力測驗。

**文字回饋**：在「數學冒險家回饋」文字框輸入最多 600 字，送出後可再次修改。只有**本人與房主**能查看該玩家的文字內容，房主可檢視回收狀態。

> ⚠️ **資料保存限制（v1.9.0）**：遊戲中的房間、動物、金錢與回合狀態仍保留在 Render 伺服器記憶體中，重啟後可能遺失。新增的 PostgreSQL **僅保存完成結算的課堂統計與房主可見的學生文字回饋**，且必須先連接環境變數 `DATABASE_URL` 才會真正寫入。歷史資料庫不會還原舊版已遺失的回饋。Render 新建的免費資料庫將於 **2026-12-04 到期**，屆時若未升級或遷移／備份，歷史資料也可能無法繼續使用。請勿把免費方案視為無期限儲存。

### v2.2.0｜個人手寫計算紙、全員翻牌動畫、12 種待機動物（2026-11-12）

**原本問題**：v1.6 的「立體旗子」看起來像旗面／對話框在移動，不符合「選貓就由貓跳到下一格」的操作期待。

**本版修改**：
- **撤回 v1.6 的旗面、旗桿與底座**；停在格子上時恢復 v1.5 以前較簡潔的小動物圖案。
- 骰子顯示點數後，暫時顯示**放大的動物本體**，依伺服器骰子點數逐格快速跳躍，約每格 0.22 秒。
- 動畫加入起跳、落地與陰影效果；抵達終點後，移動用的大動物消失，回到格子中的小圖案。
- 保留所有人同步接收移動結果、換人聚焦及使用者自由縮放的功能。
- 對偏好減少動畫的裝置，縮短過渡並降低動態效果。

**使用者感受到的差異**：選貓會看到**貓跳過每一格**；選兔子會看到**兔子跳格**，不再是奇怪的旗子或圓形視窗滑動。

### v1.6.0｜曾嘗試實體化旗子（已由 v1.6.1 取代）

**原始目標**：讓小動物棋子看起來更有桌遊的「實體棋子」質感。

**當時的變更**：加入帶有玩家代表色的旗面、旗桿、底座，並將旗子套用到移動角色與屋主標記等視覺元件。

**為何不再使用**：實際遊玩回饋顯示，旗子不像動物本身移動，反而影響辨識。**目前 v1.6.6 已不採用 v1.6 的旗子移動設計**；請勿將 v1.6 的 `public/app.js`、`public/style.css` 覆蓋到最新版。

### v1.5.1｜修正學生等待室看不到設定

**原本問題**：房主能看見四個選單，但學生等待畫面沒有顯示相同的設定；部分裝置載入的是瀏覽器快取的舊版頁面。

**本版修改**：
- 將**四項設定摘要**移到房主與學生共用的候位區，而非放在房主專屬表單裡。
- 房主改選單時透過 Socket.IO 更新房間狀態，讓一般玩家的摘要同步重繪。
- 針對 HTML、JavaScript 與 CSS 加上防快取處理；加入客戶端與伺服器版本檢查。
- 等待室可重新載入新版本；若遊戲已開始，避免突然強制刷新，改提醒在適當時機更新。

**使用者感受到的差異**：學生加入房間後，也能看見「遊戲輪數／起始金額／每題時間／課堂遊玩時間」，不必向房主口頭確認。

**更新注意**：原本已開啟、尚未具有版本檢查的舊分頁需要手動重新整理一次。

### v1.5.0｜等候設定即時同步、文字回饋、減少答題獎金

**原本問題**：候位學生看不到房主設定；結算只有題型統計、無法自己寫心得；答對題目賺錢太快，土地經營失去重要性。

**本版修改**：
- **等待室同步**：新增輪數、起始金額、每題秒數、課堂總時間的共用設定摘要；只有房主能更改，且新加入／重新連線者能收到目前設定。
- **可輸入回饋**：在「數學冒險家回饋」新增最多 600 字的文字框、字數提醒與送出按鈕；同場遊戲可重新編輯。
- **教師總覽**：房主能查看各玩家是否填寫、填寫了什麼；一般學生無法閱讀其他同學的心得。
- **經濟平衡**：保留房產價格、租金與起點薪水，但降低多種答題獎金，機會／命運卡與中後段加碼亦同步調整。

**主要獎金調整**：

| 題型／事件 | 調整前 | v1.5 起 |
|---|---:|---:|
| 小數計算 | $85 | **$45** |
| 折扣 | $95 | **$50** |
| 比價 | $130 | **$65** |
| 黑心商人 | $100 | **$55** |
| 寶箱 | $180 | **$90** |
| Boss 兩題全對 | $250 | **$140** |
| Boss 只答對一題 | $90 | **$45** |
| 中場／最後衝刺加碼 | +$30／+$60 | **+$15／+$30** |

**使用者感受到的差異**：學生更清楚一開始的規則，老師能收集實際文字心得，遊戲幣成長變慢，購買房產與資金選擇更有意義。

### v1.4.0｜無限輪、個人錯題分析、全班學習總整

**原本問題**：若只用固定輪數，課堂可能在預定 30 分鐘之前就結束；只公布財富排名，老師不容易看出學生常錯的小數題型。

**本版修改**：
- 新增並預設選取 **♾️ 無限輪**；只取消輪數限制，**仍保留 20／30／40 分鐘**的遊玩時間，以及房主手動結束功能。
- 結算時增加每人的題目統計：作答／答對／答錯、正確率、逾時次數及至多 6 題錯題解析。
- 用真正的**數學能力分類**整理常錯題型，而非按「機會格、命運格、寶箱格」混合統計。
- 顯示最多 3 個優先複習的薄弱題型及建議；全班畫面顯示**匿名**共同錯題分布。
- 房主跳過的題目不計入學生答題紀錄；重新開局重置當局學習統計。

**使用者感受到的差異**：一堂約 30 分鐘的課不會因輪數不足提早結束；結束後除了輸贏還可以回顧自己哪一類小數運算需要加強。

**技術更新**：新增 `feedback.js` 處理學習統計，個人錯題資料按玩家身分分別傳送。

### v1.3.0｜經典方格大富翁地圖、全員聚焦與資產配色

**原本問題**：v1.2 的彎曲車道不像傳統大富翁；地圖太大時大家不容易看到目前玩家；房產與玩家身分對照不夠清楚。

**本版修改**：
- 將地圖改為 **30 格的 10 欄 × 7 列方形外圈**，中間顯示標題、骰子與目前玩家資訊，不再畫車道。
- 每次換到下一位玩家，全房間的地圖會自動聚焦到該玩家附近；聚焦完仍可用縮放按鈕、滑鼠拖曳、觸控滑動自由查看。
- 新增 12 隻動物的固定代表色；棋子、房產屋主標示、排行榜及個人資產卡一致套用。
- 新增「我的資產」詳細列表，拆開顯示**現金、房產總值、總資產**，並能點選土地定位。

**使用者感受到的差異**：棋盤更像熟悉的大富翁桌遊，全班能跟著目前玩家看見落點，也更容易分辨哪間店是自己的。

**技術更新**：加入 `public/board-layout.js` 與 `public/player-colors.js`，需和前端一起部署。

### v1.2.0｜擴大至 30 格、延長答題時間、租後雙人互動

**原本問題**：舊地圖格數偏少，題目時間不足六年級學生使用紙筆計算；遊戲到中後期變化不足，踩到別人土地時只扣租金缺少互動。

**本版修改**：
- 棋盤由 **24 格擴充至 30 格**，增加房產與特殊事件；**當時採彎曲車道外觀（已被 v1.3 取代）**。
- 作答預設時間改為 **120 秒**，可延長到 150／180 秒，也可選 90 秒；Boss 題目依題計時。
- 增加以 **30 分鐘**為主的課堂遊玩時間設定，並設計中場與最後衝刺的獎勵變化。
- 踩到其他玩家房產時先收租，再由真實的**屋主與租客**同步進行猜拳或簡化版烏龜烏龜翹，勝負增加虛擬零用錢轉帳。
- 對戰提供倒數、最高回合數與平手處理，避免互動卡住全班。
- 針對 **91 題**補充已知條件、計算目標、單位與解題說明，特別加強折扣與比價題目的文字清晰度。

**使用者感受到的差異**：學生有較充足的時間理解題意、手算與檢查；更多格子與租後對戰讓 30 分鐘遊戲的節奏更有變化。

### v1.1.0｜骰子、逐格移動與事件提示動畫

**原本問題**：擲骰後玩家只看到最終格子，不知道擲出了幾點；事件紀錄藏在角落，不易注意到金額與落點；部分題目解析不夠完整。

**本版修改**：
- 加入醒目的骰子滾動和**點數揭曉**效果，骰子仍由伺服器決定，不是前端自行隨機產生。
- 角色改為依骰子點數**逐格移動**，落點與特殊事件會高亮及彈出提示；最新事件紀錄較易識別。
- 修正「原價 $80、打 7.5 折」的解說：**7.5 折 = 75%**，折後價 `80 × 0.75 = 60`，節省 `80 − 60 = 20`；明確區分「實際售價」和「省下多少」。

**使用者感受到的差異**：每次擲骰、前進與答題成功／失敗都更容易被全班看見，降低學生誤解遊戲進度的機會。

### v1.0.0｜最初可遊玩的多人數學大富翁

**初版內容**：
- 以 Node.js、Express 與 Socket.IO 提供多人房間；房主加最多五位學生可透過房間碼加入。
- 提供動物棋子、擲骰前進、現金與房產、經過起點領錢、繳交過路費，以及機會／命運類特殊格。
- 將購買土地、折扣、比價、黑心商人、寶箱、Boss 和資金不足時的救援，設計成小數應用題。
- 答題與資金、房產所有權由伺服器統一判定，避免不同裝置看到不同結算。
- 初版採 **24 格地圖**，後續經 v1.1、v1.2 與 v1.3 逐步改善可視化、題目敘述及課堂節奏。

```bash
npm install

```

```bash
npm test
```

截至 **2026-11-04（v1.6.2）**，本機執行 `npm test` 為 **44 項通過、0 項失敗**。測試主要涵蓋題庫、30 格座標、動物代碼與配色、購地與收租、對戰判定、時間／輪數結算、等待室設定、學習回饋與權限限制。**自動單元測試通過不代表已完成真實 6 人同時在線的正式環境壓力測試**；實際上課前建議至少用兩台裝置試玩。

## GitHub 與 Render 部署

### 已有 GitHub 專案：更新既有檔案

1. 在學生遊戲**結束後**再更新，以免 Render 重啟使目前房間遺失。
2. 確認 GitHub `main` 分支是你目前要使用的版本，先保留備份。
3. 更新程式時，將完整新版專案的檔案**依相同路徑覆蓋**，例如 `public/app.js` 覆蓋 `public/app.js`；不要直接把整個 ZIP 當成一個檔案傳到 GitHub。
4. **如果只更新 README**，僅替換根目錄的 `README.md` 即可，**不需要重新上傳整個程式或更改 `package.json` 版本號**。
5. Commit 到 `main` 後，Render 若啟用自動部署，可能因新 commit 重啟服務。確認服務狀態為 **Live** 後再請學生入場。

### 首次部署：Render Blueprint

在儲存庫根目錄保留 `render.yaml`（與 `package.json` 同層），到 [Render Dashboard](https://dashboard.render.com/) 建立 **New → Blueprint**，選擇該儲存庫及 `main` 分支，Blueprint Path 使用 `render.yaml`。

`render.yaml` 預設內容：Node Web Service、Singapore、Free、`npm install --omit=dev`、`npm start`、健康檢查 `/health`。也可以手動建立 Node Web Service，使用相同的 Build 與 Start 指令。

## 已知限制與排除方式

| 狀況 | 說明／建議 |
|---|---|
| 學生看不到新版等待室設定 | 確認 Render 已部署最新 commit，再讓學生重新整理舊分頁；v1.5.1 後有版本偵測與防快取改進 |
| 動物圖案仍是舊選項 | 確認 GitHub 與部署版本均是 v1.6.2；重新整理瀏覽器，並確認 `board.js`、`public/app.js`、`public/player-colors.js` 使用同一份動物清單 |
| 棋子變回旗子 | 代表誤用了 v1.6 的前端檔案；請改用 **v1.6.1／v1.6.2** 的 `public/app.js` 和 `public/style.css` |
| 無限輪仍然結束 | 無限輪只取消**輪數限制**，仍受設定的 20／30／40 分鐘限制 |
| 學生突然無法繼續先前遊戲 | Render 重新部署、重啟或房間被清除後，記憶體中的進度不會自動恢復 |
| 文字回饋不見 | v1.9.0 起可用 PostgreSQL 保存結算後回饋，但必須先設 `DATABASE_URL`；未連線仍僅留在記憶體，資料庫到期後也無法無限期保留 |
| 多人操作時間不同步 | 檢查各裝置網路與 Render 服務狀態；以伺服器的狀態和計時為準 |
